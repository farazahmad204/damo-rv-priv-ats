# Milk-V Megrez (ESWIN EIC7700X, SiFive P550)

Runs the suites on real hardware, without a simulator. The test ELF is sent
over the UART to a minimal M-mode runner that replaces OpenSBI in the board's
SPI boot chain ([ACT-Runner](https://github.com/farazahmad204/ACT-Runner-for-Vision-Five-2-RISC-V-Board-),
board `milkv_megrez_eic7700x`). The runner loads the ELF, starts it in M-mode
on **hart 1** and reports `PASS`/`FAIL` from the `tohost` value written by
`RVMODEL_HALT_PASS` (1) or `RVMODEL_HALT_FAIL` (3). The suite's own output
(per-case results and summary) comes out on the same UART.

```bash
cd Hypervisor_CSR
make clean && make CONFIG=milkv-megrez-p550 CROSS_COMPILER=/path/to/riscv64-unknown-elf-
```

| Item | Value | Source |
|---|---|---|
| Load window | `0x90000000`-`0xB0000000` (`MEM_BASE=0x90000000`) | runner payload window |
| Boot hart | 1 (`RVMODEL_BOOT_HARTID`) | runner starts ELFs on hart 1 |
| UART0 | `0x50900000`, DesignWare 8250, register shift 2, 16-bit accesses, 115200 baud from 200 MHz (divisor 109) | runner board config |
| CLINT | `0x02000000`; hart 1 MSIP `+0x4`, MTIMECMP `+0x4008`; mtime 1 MHz | runner board config |
| `hvip` | cleared in `RVMODEL_BOOT` (reads `0x440` at runner entry) | csr_probe on the board |

## Extensions

`rvtest_config.h` is generated by riscv-unified-db from `milkv-megrez-p550.yaml`
(the ACT configuration for this board). The suites only check which extensions
are declared, not spec versions.

The P550 implements the privileged architecture **1.11** and the hypervisor
extension as **draft 0.6**. The yaml declares S/Sm 1.12 and H 1.0 only so that
UDB accepts H; the hardware has no `menvcfg`, `senvcfg`, `henvcfg`,
`htimedelta` or `stimecmp`. Failures that come from H 0.6 vs ratified H 1.0
(or priv 1.11 vs 1.12+) are expected and are not hardware bugs.

## Absent CSRs

The shared reset and set-up code assumes priv 1.12+ and touches `menvcfg`,
`henvcfg` and `htimedelta`, which trap on this core and would stop every
suite before its first test. `PLATFORM_ABSENT_CSRS` in `platform_config.h`
lists them; the M-mode trap handler emulates an unarmed access to one of
them as read-zero / write-ignored. Tests that arm the trap still see it.

Checked on Sail 0.14.1 with the board's priv-1.11 + H configuration: without
the emulation every suite stops at `csrr menvcfg` (the same trap as on the
board); with it, 21 of the 23 hypervisor suites run to completion. `Sha`
stops at `mstateen0` (the P550 does not implement Sha/Ssstateen).
